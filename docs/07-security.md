# 07. 보안 정책

**대상**: 이 저장소를 사용하거나 수정하는 모든 사람, 그리고 이 저장소에서 작업하는 모든 AI 에이전트
**범위**: 크레덴셜 보관, 2단계 인증, 로그 위생, 개인정보, 공개 저장소 취급, 사고 대응

---

## 0. 전제

이 도구는 **개인 웹메일 계정의 아이디, 비밀번호, TOTP 시크릿**을 모두 보유해야 동작합니다. 즉 이 저장소가 놓인 컴퓨터를 장악한 사람은 곧 메일 계정을 장악합니다. 아래 규칙은 편의를 위해 완화할 수 있는 권고가 아니라, 그 전제 위에서의 최소 요구사항입니다.

---

## 1. 크레덴셜 보관

### 1.1 절대 규칙

- **`.env`는 절대 커밋하지 않습니다.** 이미 `.gitignore`의 첫 항목으로 등재되어 있습니다.
- **`.env`를 클라우드 동기화 폴더에 두지 않습니다.** 자동 백업 대상 폴더에 저장소를 두었다면 `.env`만이라도 제외 설정을 하십시오.
- **`.env`를 메신저나 메일로 전달하지 않습니다.** 어떤 형태로든 전송된 비밀은 회수할 수 없습니다.
- 파일 권한을 좁힙니다. Windows 파일 속성 → 보안에서 본인 계정 외의 사용자를 제거하는 것을 권장합니다.

### 1.2 채택된 시크릿 동기화 전략

이 프로젝트가 확정한 방식은 **패스워드 매니저 + `.env.example` 템플릿** 한 가지입니다.

```
새 컴퓨터에서의 절차
  1. 저장소를 클론한다
  2. copy .env.example .env
  3. 패스워드 매니저에서 값을 꺼내 .env를 손으로 채운다
```

- 실제 비밀값의 **정본은 패스워드 매니저**에 있습니다. 저장소는 템플릿만 들고 있습니다.
- **SOPS, git-crypt, dotenvx 같은 "암호화해서 커밋하는" 방식은 도입하지 않습니다.** 암호문이라도 저장소에 비밀이 들어가면 키 관리와 키 회전 부담이 새로 생기고, 저장소가 공개될 때 오프라인 공격 대상이 됩니다.
- **키 패리티 유지**: `.env`에 새 키를 추가하면 **반드시 같은 커밋에서 `.env.example`에도 추가**합니다. 값은 넣지 않고 자리표시자만 둡니다. 이 규칙이 깨지면 다른 컴퓨터에서 설정이 조용히 누락된 채 실행됩니다.

`.env.example`에 넣어도 되는 것과 안 되는 것:

| 항목 | 예시 | 가부 |
|---|---|---|
| 키 이름 | `MAILON_TOTP_SECRET=` | 가능 |
| 자리표시자 | `MAILON_ID=your_id@example.com` | 가능 |
| 공개 URL 기본값 | `MAILON_LOGIN_URL=https://mailon.kr/` | 가능 |
| 실제 아이디 | 실제 계정 주소 | **금지** |
| 실제 비밀번호 | 실제 값 | **금지** |
| 실제 TOTP 시크릿 | 실제 Base32 문자열 | **금지** |

문서나 테스트에 TOTP 시크릿 예시가 필요하면 표준 더미값(`JBSWY3DPEHPK3PXP`)을 사용합니다.

### 1.3 TOTP 시크릿의 등급

TOTP Base32 시크릿은 **비밀번호와 동일 등급의 비밀**입니다. 유출되면 2단계 인증이 사실상 무력화됩니다. 비밀번호를 다루는 모든 규칙(커밋 금지, 로그 금지, 전달 금지)이 그대로 적용됩니다.

## 2. 로그와 출력 위생

### 2.1 절대 기록하지 않는 것

- 비밀번호 값
- TOTP Base32 시크릿
- 생성된 6자리 TOTP 코드

로그, 예외 메시지, 테스트 출력, 화면 출력, 커밋 메시지 어디에도 남기지 않습니다.

### 2.2 허용되는 대체 표현

진단에는 값 대신 **값의 성질**만 남깁니다.

| 금지 | 허용 |
|---|---|
| 비밀번호 값을 그대로 출력 | 길이만 출력 (`len(pw)=9`) |
| TOTP 시크릿 출력 | 시크릿 존재 여부 (`secret loaded: yes`) |
| 환경변수 전체 덤프 | 필요한 키 이름 목록만 |

예외 트레이스에 환경변수를 통째로 덤프하지 마십시오. 구성 로더는 설계상 비밀값을 로그로 내보내지 않습니다. 새 코드를 추가할 때 이 성질을 깨뜨리지 마십시오.

### 2.3 산출물과 진단 파일

| 경로 | 성격 | 취급 |
|---|---|---|
| `data/mails/` | 수집된 메일 본문 (개인정보) | 무시 대상 유지. 외부 공유 금지 |
| `data/attachments/` | 첨부 파일 (개인정보) | 무시 대상 유지. 외부 공유 금지 |
| `data/state.db` | 제목·발신자 등 메타데이터 (개인정보) | 무시 대상 유지 |
| `logs/sync-*.log` | 실행 로그. 제목·주소가 포함될 수 있음 | 무시 대상 유지. 공유 전 검토 |
| `logs/probe-*` | 화면 구조 덤프 | 검토 후 삭제 권장 |
| `logs/send-attempts.jsonl` | 발송 시도 요약 | 무시 대상 유지 |
| 스크린샷 | 로그인 폼이나 메일 내용이 찍힐 수 있음 | **즉시 삭제** |

- `.gitignore`가 `data/`와 `logs/` 전체를 제외하고 있으므로 상태 DB(`data/state.db`)도 함께 제외됩니다. 상태 DB나 다른 `.db` 파일을 **다른 경로로 옮기는 변경을 한다면 무시 규칙을 먼저 추가**하십시오.
- 브라우저 세션 상태 파일(`*.state.json`, `auth-state.json`)도 무시 대상입니다. 세션 쿠키가 들어 있으므로 첨부나 공유 대상이 되어서는 안 됩니다.
- 문제 보고를 위해 로그를 붙여야 한다면, **주소·제목·본문·첨부 파일명을 지운 뒤** 붙이십시오.

## 3. 2단계 인증과 계정 잠금 방지

### 3.1 2FA는 우회하지 않습니다

이 서비스의 로그인은 **아이디 + 비밀번호 + Google OTP(TOTP)** 세 가지를 모두 요구합니다. 이 도구는 2FA를 우회하지 않고, 사용자가 보유한 시크릿으로 정당한 코드를 생성해 정상 절차를 따릅니다. 2FA를 끄거나 우회하는 방향의 변경은 이 프로젝트에서 허용되지 않습니다.

### 3.2 잠금 방지 규칙

로그인 실패 응답은 아이디 오류, 비밀번호 오류, OTP 오류를 **구분해 주지 않습니다.** 원인을 모른 채 반복 시도하면 계정 잠금으로 직행합니다.

| 규칙 | 값 |
|---|---|
| 연속 실패 허용 횟수 | **3회에서 중단**하고 원인을 먼저 조사 |
| 재시도 간 최소 간격 | **30초 이상** |
| OTP를 소모하는 테스트 간격 | **1분 이상** (같은 코드는 한 창에서 1회만 유효) |
| 자동 실행 주기 | **10분 미만 금지** |

비밀번호를 추측해 반복 시도하는 행위는 어떤 상황에서도 금지입니다. 비밀번호를 모른다면 정식 절차로 재설정하십시오.

### 3.3 시각 동기화

TOTP는 시계에 의존합니다. 코드 생성 후 유효 시간이 충분히 남았을 때 제출해야 하며, 컴퓨터 시계가 어긋나면 정상 크레덴셜로도 계속 실패해 잠금 위험이 커집니다. 실패가 반복되면 비밀번호를 의심하기 전에 시각 동기화부터 확인하십시오.

## 4. 사용 범위

- **본인 계정 전용**입니다. 타인의 메일함에 접근하는 용도로 사용하지 마십시오. 위임받았다고 하더라도 이 도구의 범위를 벗어납니다.
- **개인 백업 목적**으로만 사용합니다. 대량 수집, 재배포, 상업적 이용은 대상 서비스의 이용 조건에 반할 수 있습니다.
- **서비스에 부하를 주지 않습니다.** 짧은 주기의 반복 실행, 병렬 다중 세션 실행을 하지 마십시오.
- **내부 API를 직접 두드리지 않습니다.** 로그인 암호화(RSA)나 CSRF 토큰 처리를 파이썬에서 수동으로 재구현하려 하지 마십시오. 인증 관련 처리는 전부 **브라우저 안의 JS에 맡깁니다.** 직접 재구현은 깨지기 쉬울 뿐 아니라, 비밀값을 브라우저 밖으로 꺼내 다루게 되어 노출면을 넓힙니다.
- **세션 재사용에 의존하지 않습니다.** 세션 상태 저장은 로컬 디버깅 용도이며, 정기 수집은 매 실행 새로 로그인하는 방식을 유지합니다.

## 5. 공개 저장소 취급

이 저장소는 **공개(public)를 전제로 관리**됩니다. 공개하거나 fork하기 전에 아래를 반드시 확인하십시오.

### 5.1 공개 전 점검 목록

- [ ] `.env`가 추적되고 있지 않은가 (`git ls-files | findstr .env` 결과에 `.env.example`만 있어야 함)
- [ ] `data/`가 커밋에 포함되지 않았는가 (메일 본문·첨부·상태 DB)
- [ ] `logs/`가 커밋에 포함되지 않았는가
- [ ] 스크린샷 이미지가 저장소 안에 남아 있지 않은가
- [ ] 문서와 코드 주석에 실제 이름, 실제 메일 주소, 실제 소속이 남아 있지 않은가
- [ ] 과거 이력(`git log -p`)에 비밀이 들어간 적이 없는가

### 5.2 예시는 전부 합성값으로

실제 메일 제목, 본문, 첨부 파일명, 메일 식별자(UID), 발신자 이름과 주소는 **모두 개인정보**입니다. 문서나 테스트에 그대로 옮기지 마십시오. 대신 다음과 같은 합성값을 사용합니다.

| 종류 | 사용할 값 |
|---|---|
| 도메인 | `example.com`, `example.org` |
| 이름 | `홍길동` |
| 소속 | `예시연구원 - 연구지원팀` |
| 메일 UID | `1000001` |
| TOTP 시크릿 | `JBSWY3DPEHPK3PXP` |
| 로컬 경로 | `C:\Users\<사용자명>\Documents\mailon-backup` |

경로 예시에 실제 Windows 사용자 계정명을 넣지 마십시오. 계정명 자체가 신원 정보입니다.

### 5.3 이슈와 PR

버그 리포트에 로그를 붙일 때 메일 제목, 주소, 본문 조각이 함께 붙는 사고가 가장 흔합니다. 붙여넣기 전에 항상 한 번 읽고 지우십시오.

## 6. 사고 대응 — 비밀이 커밋된 경우

**이미 원격에 푸시된 비밀은 유출된 것으로 간주합니다.** 저장소를 비공개로 되돌리거나 커밋을 지워도, 그 사이에 누가 받아 갔는지는 알 수 없습니다.

### 6.1 순서 (순서가 중요합니다)

1. **먼저 크레덴셜을 회전합니다.**
   - 계정 비밀번호를 즉시 변경합니다.
   - Google OTP를 초기화하고 **새 시크릿으로 재등록**합니다. 폰의 인증 앱도 다시 등록합니다.
   - 새 값으로 로컬 `.env`를 갱신합니다.
2. **그 다음 이력을 정리합니다.**
   - `git filter-repo`로 해당 파일과 문자열을 전체 이력에서 제거합니다.
   - 정리된 이력을 원격에 강제로 반영합니다.
   - 저장소를 clone/fork한 사람이 있다면 각자 다시 clone하도록 알립니다.
3. **재발을 막습니다.**
   - `.gitignore`에 누락된 항목이 없는지 확인합니다.
   - 어떤 경로로 비밀이 스테이징되었는지 확인하고, 같은 실수가 반복될 수 있는 지점을 고칩니다.

이력 정리를 먼저 하고 회전을 미루면, 그 사이에 유출된 비밀이 그대로 유효한 상태로 남습니다. **회전이 항상 먼저입니다.**

### 6.2 아직 푸시되지 않았다면

로컬 커밋 단계에서 발견했다면 이력에서 제거하는 것만으로 충분할 수 있습니다. 다만 원격에 올라간 적이 없다는 점을 **확실히 확인한 경우에만** 해당합니다. 조금이라도 불확실하면 §6.1의 회전 절차를 그대로 따르십시오.

## 7. 코드를 수정할 때 지켜야 할 것

- 새로 추가하는 로그 문장이 비밀값을 찍지 않는지 확인합니다.
- 예외 메시지에 사용자 입력(수신자 주소, 제목, 본문)을 통째로 넣지 않습니다. 발송 명령이 표준출력에 **오류 종류만** 출력하는 것도 같은 이유입니다.
- 테스트에 실제 크레덴셜을 하드코딩하지 않습니다. 오프라인 테스트는 네트워크와 크레덴셜 없이 통과해야 합니다.
- 실패하는 테스트를 지워서 통과시키지 않습니다.
- 안전장치를 우회하는 옵션을 새로 만들지 않습니다. 특히 발송 승인 게이트를 생략하는 환경변수나 설정을 추가하지 마십시오.
