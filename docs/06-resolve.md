# 06. 수신자 이름 해석 (resolve)

**목적**: 이름만 알고 이메일 주소를 모르는 수신자를, 웹메일 쓰기 화면의 **주소 자동완성**을 이용해 후보 목록으로 확인
**파일**: `mailon/resolve.py` + `mailon/main.py`
**CLI**: `python -m mailon.main resolve --name <이름> [--json]`

---

## 1. 한 줄 요약

`resolve`는 **읽기 전용** 명령입니다. 쓰기 화면을 열어 수신자 입력란에 이름을 입력하고, 화면에 뜨는 자동완성 목록을 긁어와 구조화해 출력할 뿐입니다. **발송 트리거는 어떤 경로로도 호출되지 않습니다.**

주소를 확인한 다음, 그 주소를 [05-send.md](05-send.md)의 `--to`에 넣는 것이 표준 사용 흐름입니다.

---

## 2. 플래그 레퍼런스

`mailon/main.py`의 `build_parser()` 정의 기준입니다.

| 플래그 | 필수 | 기본값 | 설명 |
|---|---|---|---|
| `--name` | **필수** | 없음 | 수신자 입력란에 입력할 이름 문자열 |
| `--json` | 선택 | 꺼짐 | 결과를 한 줄 JSON으로 출력. 로그는 표준에러로 분리 |

### 종료 코드

| 코드 | 의미 |
|---|---|
| **0** | 정상 종료. 후보가 0개여도 0입니다 (조회 자체는 성공) |
| **2** | 로그인 실패(`LoginError`) 또는 브라우저 오류(`BrowserError`) |

`.env` 설정이 누락되어 구성 로딩이 실패하면 종료 코드 1로 끝납니다.

---

## 3. 읽기 전용 보장

| 항목 | 내용 |
|---|---|
| 화면 조작 | 쓰기 화면 열기 → 수신자 입력란 포커스 → 이름 입력 → 자동완성 목록 읽기 |
| 호출하지 않는 것 | 발송 트리거, 보내기 버튼 클릭, 임시저장, 폼 제출 |
| 브라우저 세션 | 기본 세션 이름에 `-resolve` 접미사를 붙인 **전용 세션** (예: `mailon-sync-resolve`) |
| 남는 흔적 | 메일함에는 아무 변화가 없습니다. 로그에 조회 결과 요약만 남습니다 |

전용 세션을 쓰는 이유는 발송과 동일합니다. 동기화 세션을 공유하면 쓰기 화면으로 이동하는 순간 **동시에 돌고 있던 동기화 작업이 죽습니다.**

다만 이 명령도 **실제 계정으로 실제 로그인을 수행**합니다. 따라서 남용하면 로그인 실패 누적으로 계정이 잠길 수 있습니다. 연속 실행은 [07-security.md](07-security.md)의 간격 규칙을 따르십시오.

---

## 4. 동작 순서

```
1. 로그인            ID + 비밀번호 + TOTP (전용 -resolve 세션)
2. 쓰기 화면 열기     window._tbar.compose() 호출 후 3초 대기
3. 네트워크 기준선 초기화
4. 이름 입력         수신자 입력란(#adr-to-ipt_ta)에 포커스 후 타이핑
                    실패 시 네이티브 setter + 키 이벤트 폴백
5. 자동완성 대기      약 2.5초
6. 목록 수집          자동완성 그리드의 셀 텍스트를 모두 읽음
7. 파싱/중복 제거     Candidate 목록으로 변환
8. 출력              텍스트 또는 JSON
```

4단계의 폴백이 존재하는 이유는, 자동화 환경에서 일반 타이핑 경로가 실패하는 경우가 있기 때문입니다. 그때는 네이티브 setter로 값을 넣고 키 이벤트를 직접 발생시켜 자동완성 위젯이 변경을 인지하게 만듭니다.

---

## 5. 출력 형식

### 5.1 Candidate 구조

자동완성 셀 하나가 후보 하나로 변환됩니다.

| 필드 | 설명 |
|---|---|
| `group` | 후보의 출처 분류 (§5.2) |
| `name` | 큰따옴표로 감싸인 표시 이름 |
| `email` | 꺾쇠 안의 이메일 주소 |
| `org` | 소속. 셀 뒷부분에 `::` 구분자가 있을 때만 채워지고, 없으면 빈 문자열 |

### 5.2 group 분류

| 셀 앞머리 라벨 | `group` 값 | 의미 |
|---|---|---|
| `Organization` | `organization` | 조직 주소록 |
| `Contacts` | `contacts` | 개인 주소록 |
| `대표 도메인` | `history` | 도메인/이력 기반 추천 |
| (해당 없음) | `unknown` | 분류 라벨을 인식하지 못한 셀 |

### 5.3 중복 제거 규칙

`(name, email, group)` 세 값이 모두 같은 후보는 **처음 나온 것만 남기고 이후는 버립니다.** 순서는 화면에 나타난 순서를 그대로 유지합니다. 같은 이메일이라도 `group`이 다르면 별개의 후보로 남습니다. 어느 주소록에서 나온 주소인지가 판단에 필요하기 때문입니다.

이름과 이메일 패턴(`"이름" <주소>`)이 없는 셀, 예를 들어 "내용이 없습니다" 같은 안내 문구 셀은 후보에서 제외됩니다.

### 5.4 텍스트 출력

후보 한 줄당 `group`, `"이름" <이메일>`, `소속`이 탭으로 구분되어 출력되고, 마지막에 요약 줄이 붙습니다.

```
organization	"홍길동" <hong@example.com>	예시연구원 - 연구지원팀
contacts	"홍길동" <hong@example.org>	
OK: 2 candidate(s) for '홍길동'; POST=1
```

두 번째 줄처럼 소속이 비어 있는 후보도 정상입니다 (개인 주소록 항목은 소속 정보가 없는 경우가 많습니다).

### 5.5 JSON 출력

```bash
.venv\Scripts\python -m mailon.main resolve --name 홍길동 --json
```

```json
{"status":"ok","query":"홍길동","candidates":[{"group":"organization","name":"홍길동","email":"hong@example.com","org":"예시연구원 - 연구지원팀"},{"group":"contacts","name":"홍길동","email":"hong@example.org","org":""}],"post_count":1}
```

`--json`을 주면 로그가 표준에러로 분리되므로 **표준출력은 JSON 한 줄만** 나옵니다.

실패 시에는 다음 형식이 표준출력에 나옵니다.

```json
{"status":"error","error_code":"LoginError"}
```

`--json` 없이 실패하면 표준에러에 `FAIL: LoginError` 형태로 출력됩니다.

## 6. 사용 시나리오

### 6.1 이름만 아는 수신자에게 메일 보내기

```bash
REM 1단계. 이름으로 주소 후보 확인
.venv\Scripts\python -m mailon.main resolve --name 홍길동
```

```
organization	"홍길동" <hong@example.com>	예시연구원 - 연구지원팀
OK: 1 candidate(s) for '홍길동'; POST=1
```

```bash
REM 2단계. 확인한 주소로 드라이런
.venv\Scripts\python -m mailon.main send ^
  --to hong@example.com ^
  --subject "자료 요청" ^
  --body "요청하신 자료를 정리해 보내드립니다." ^
  --dry-run
```

```bash
REM 3단계. 주소를 눈으로 다시 확인한 뒤 실발송
.venv\Scripts\python -m mailon.main send ^
  --to hong@example.com ^
  --subject "자료 요청" ^
  --body "요청하신 자료를 정리해 보내드립니다." ^
  --confirm-send
```

### 6.2 동명이인 판별

같은 이름의 후보가 여러 개 나오면 `org` 값으로 구분합니다. 소속이 비어 있어 판별이 불가능하다면 **추측하지 말고** 상대방에게 직접 주소를 확인하십시오. 잘못된 주소로 나간 메일은 회수할 수 없습니다.

### 6.3 다른 프로그램에서 호출

`--json` 출력을 파싱해 `candidates` 배열이 정확히 하나일 때만 자동으로 진행하고, 0개이거나 2개 이상이면 사람의 확인을 요구하도록 만드는 것이 안전합니다.

---

## 7. 한계

- **후보는 웹메일이 걸러 준 결과 그대로**입니다. 이 도구는 자체 필터링을 하지 않습니다. 즉 입력한 이름과 관련이 적어 보이는 항목이 섞일 수 있으며, 최종 판단은 사람이 해야 합니다.
- 자동완성 위젯이 응답하기 전에 목록을 읽으면 후보가 0개로 나올 수 있습니다. 결과가 비었는데 확실히 존재하는 이름이라면 잠시 후 한 번 더 시도하십시오 (연속 실행 간격은 [07-security.md](07-security.md) 참조).
- 웹메일 내부 구조(쓰기 화면 진입점, 수신자 입력란, 자동완성 그리드 식별자)에 결합되어 있어 사이트 개편 시 깨질 수 있습니다.
- 셀 텍스트 파싱과 중복 제거 로직은 `tests/test_offline.py`가 더미 데이터로 덮고 있습니다. 브라우저 조작 부분은 오프라인 테스트로 검증되지 않습니다.

---

## 8. 문제 해결

| 증상 | 확인 순서 |
|---|---|
| 후보 0개 | 이름 철자 확인 → 잠시 후 재시도 → `logs/sync-YYYY-MM-DD.log`에서 수집된 셀 개수 확인 |
| `FAIL: LoginError` | [01-login.md](01-login.md)의 진단 절차. 시각 동기화와 TOTP 유효 시간 확인 |
| `FAIL: BrowserError` | `agent-browser doctor --offline --quick` 후 좀비 세션 정리 |
| 동기화 작업이 같이 죽음 | 세션 이름이 `-resolve` 접미사로 분리되어 있는지 확인. 기본 설정이면 자동으로 분리됩니다 |
