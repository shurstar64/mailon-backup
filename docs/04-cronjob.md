# 04. Windows 작업 스케줄러 자동화 가이드

**목적**: 매시간 `mailon.main sync`를 자동으로 실행하여 1년 365일 무인 운영 환경을 구축합니다.
**파일**: `run_sync.bat`, `register_task.ps1`
**사용자 작업**: 관리자 권한 PowerShell에서 `register_task.ps1`을 1회 실행합니다.

---

## 1. 시스템 구조

```
┌─────────────────────────────────────────────┐
│ Windows 작업 스케줄러 (Task Scheduler)        │
│ ├─ 작업 이름: "MailonSync"                   │
│ ├─ 트리거: 매 1시간마다 무한 반복             │
│ ├─ 실행 프로그램: run_sync.bat                │
│ ├─ 실행 계정: 현재 사용자 (Interactive)       │
│ └─ 설정: 배터리 사용 시에도 실행, 지연 시 재시도 │
└─────────────────────────────────────────────┘
              │
              ▼ (매시간 실행)
┌─────────────────────────────────────────────┐
│ run_sync.bat                                 │
│ ├─ PATH 설정 (agent-browser 및 Node.js 포함)  │
│ ├─ python -m mailon.main sync 실행           │
│ ├─ 종료 코드(Exit Code) 전파                 │
│ └─ 30일 경과한 로그 파일 자동 삭제            │
└─────────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────────┐
│ Python 동기화 로직                           │
│ ├─ 로그인 → 목록 조회 → 신규 메일 저장        │
│ ├─ logs/sync-YYYY-MM-DD.log에 상세 기록       │
│ └─ 종료 코드: 0(성공), 2(로그인/설정 오류),    │
│    3(크래시), 10(venv 없음), 11(브라우저 없음) │
└─────────────────────────────────────────────┘
```

---

## 2. 작업 등록 방법 (최초 1회)

### 2.1 관리자 권한 PowerShell 실행

1. Windows 검색창에서 `PowerShell`을 입력합니다.
2. `Windows PowerShell` 앱을 우클릭하여 **관리자 권한으로 실행**을 선택합니다.
3. 프로젝트가 설치된 디렉토리로 이동합니다.

```powershell
cd C:\Users\<사용자명>\Documents\mailon-backup
```

### 2.2 등록 스크립트 실행

```powershell
powershell -ExecutionPolicy Bypass -File register_task.ps1
```

**출력 예시**:
```
Creating task 'MailonSync'...
Done. Task 'MailonSync' is scheduled.
Next run: 2026-07-31 15:05:00

Useful commands:
  schtasks /Query /TN MailonSync /V /FO LIST   (상세 정보 확인)
  schtasks /Run   /TN MailonSync               (즉시 실행)
  schtasks /End   /TN MailonSync               (실행 중인 작업 강제 종료)
  schtasks /Delete /TN MailonSync /F           (작업 삭제)
```

---

## 3. 주요 파일 상세 설명

### 3.1 `run_sync.bat` (진입점)

작업 스케줄러가 실제로 호출하는 배치 파일입니다. 다음과 같은 안전장치가 포함되어 있습니다.
- **PATH 보정**: 작업 스케줄러는 최소한의 환경 변수로 실행되므로, `agent-browser`가 설치된 `%APPDATA%\npm`과 Node.js 경로를 PATH 맨 앞에 추가합니다.
- **의존성 검사**: Python 가상환경(`.venv`)이나 `agent-browser`가 없으면 전용 종료 코드(10, 11)를 반환하며 종료합니다.
- **로그 로테이션**: `forfiles` 명령을 사용하여 `logs/` 폴더 내 30일이 지난 로그 파일을 자동으로 삭제합니다.

### 3.2 `register_task.ps1` (등록 스크립트)

- **실행 계정**: `SYSTEM` 계정이 아닌 **현재 대화형 사용자** 권한으로 등록합니다. 이는 `agent-browser`가 사용자의 Chrome 프로필에 접근하기 위해 필수적입니다.
- **반복 설정**: 등록 약 2분 뒤 첫 실행을 시작하며, 1시간 주기로 10년간 반복되도록 설정합니다.
- **중복 실행 방지**: 이전 작업이 끝나지 않았을 경우 새로운 실행을 무시(`IgnoreNew`)하여 브라우저 세션 충돌을 막습니다.
- **시간 제한**: 한 번의 실행이 30분을 초과하면 강제로 종료하여 시스템 리소스 낭비를 방지합니다. (전체 백업은 수동으로 실행해야 합니다.)

## 4. 운영 및 디버깅 가이드

### 4.1 작업 상태 확인

명령 프롬프트(cmd)에서 다음 명령으로 작업의 마지막 실행 결과와 다음 예정 시각을 확인할 수 있습니다.
```cmd
schtasks /Query /TN MailonSync /V /FO LIST
```
- `Status: Ready`: 정상 대기 중
- `Last Run Result: 0`: 마지막 실행 성공 (0 이외의 값은 에러 발생)
- `Run As User: <Windows 사용자명>`: 올바른 계정으로 등록되었는지 확인

### 4.2 디버깅 순서 (문제가 생겼을 때)

1. **로그 확인**: `logs/sync-YYYY-MM-DD.log` 파일의 마지막 부분을 확인하여 에러 메시지를 읽습니다.
2. **수동 실행 테스트**: `run_sync.bat`을 직접 실행하여 콘솔에 뜨는 에러를 확인합니다.
3. **로그인 점검**: `python -m mailon.main login` 명령으로 계정 비밀번호나 TOTP 시크릿이 유효한지 확인합니다.
4. **페이지 덤프**: `python -m mailon.main probe` 명령으로 현재 mailon.kr의 HTML 구조를 덤프하여 UI 변경 여부를 확인합니다.

### 4.3 Windows 환경 주의사항

- **한글 깨짐**: 콘솔에서 한글이 깨져 보인다면 `chcp 65001` 명령으로 코드페이지를 UTF-8로 변경하세요. (파일 저장에는 영향을 주지 않습니다.)
- **비밀번호 특수문자**: 비밀번호에 `!` 문자가 포함된 경우, 배치 파일에서 `cmd /V:ON`(지연된 확장)을 사용하면 문자가 사라질 수 있으므로 주의해야 합니다. 본 프로젝트의 배치 파일은 이 기능을 사용하지 않도록 설계되었습니다.
- **절전 모드**: PC가 절전 모드일 때는 작업이 실행되지 않습니다. 깨어난 후 `StartWhenAvailable` 설정에 의해 놓친 작업이 1회 실행됩니다.

---

## 5. 윤리적 사용 및 남용 방지

- **실행 간격**: 반복 주기를 **10분 미만**으로 설정하지 마세요. mailon.kr은 공공기관(KISTI)에서 운영하는 서비스이며, 과도한 요청은 서버 부하를 유발하고 계정 차단의 원인이 될 수 있습니다. 1시간 주기를 권장합니다.
- **사용 범위**: 본 도구는 개인적인 백업 및 동기화 용도로만 사용해야 합니다. 대규모 자동화나 서비스 남용은 금지됩니다.
- **보안**: `.env` 파일에 저장된 크레덴셜이 유출되지 않도록 관리자 권한이 없는 다른 사용자의 접근을 제한하세요.
